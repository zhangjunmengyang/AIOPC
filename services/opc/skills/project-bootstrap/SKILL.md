# 项目启动：像顶级顾问一样接手

目标不是写一份漂亮报告，而是让之后每一次工作（起名、Logo、落地页、社媒、投放、复盘）都站在同一份准确、可维护的事实上。产出是项目目录里的几份文件，它们就是这个项目的记忆。

## 0. 先确定在哪个项目里

工作目录是 `workspace/projects/<id>` 时就是这个项目；否则先问清楚，或用 `create_project` 新建（只需名称）。调用 `get_project_brief(project_id)`，看实验室和项目已经知道什么，**已有的事实直接沿用，不要求用户重复。**

## 1. 盘点材料（不评价，先收齐）

- 用户给的文件放进 `knowledge/`，按主题命名；网页（落地页、竞品页、应用商店页）抓取正文存为 `knowledge/<来源>.md`，文首写原始 URL 和抓取日期。
- 在 `knowledge/SOURCES.md` 维护一张表：材料、来源、日期、可信度（用户亲述 / 公开页面 / 数据 / 二手）。
- 图片、截图、视频放 `assets/`，在 SOURCES 里登记用途。

## 2. 抽取事实，分清四类

逐份读材料，把信息分到四类。每条都标来源（文件名或 URL），没有来源的不进“事实”：

| 类型 | 含义 | 例子 |
| --- | --- | --- |
| 事实 | 有出处、可核对 | 已上线 iOS；月活 1.2k（来源：后台截图 11-01） |
| 主张 | 我们对外说的话，未必被证实 | “最快的笔记工具” |
| 假设 | 我们相信但没验证 | 目标用户是独立开发者 |
| 未知 | 做决定前需要知道的 | 付费意愿、主要获客渠道 |

不确定的数字写“约”并注明口径；绝不编造用户评价、数据、案例或背书。

## 3. 只问最关键的问题

读完后列出会改变决策的空白，一轮最多 5 个问题，每个问题附上你建议的默认答案和理由，让用户可以只回“同意”。典型的高杠杆问题：

- 这个项目现在最想达成的一个结果是什么（3 个月内）？用什么数字判断？
- 最重要的一类用户是谁，他们现在用什么替代方案？
- 我们能拿出的最强证据是什么（真实用户、数据、作品）？
- 有什么不能说、不能做（品牌红线、合规、个人身份）？
- 预算和每周能投入的时间？

用户回答后更新文件；没回答的保留在“未知”。

## 4. 写进项目记忆

在项目目录维护下面这些文件。**每个文件都要短、准、当前**：更新已有内容，不追加重复段落；过时的信息改掉，重要的变更写进决策记录。

| 文件 | 内容 |
| --- | --- |
| `CONTEXT.md` | 一句话说明；用户与问题；现在的替代方案；产品阶段与已交付能力；核心指标与当前数值；事实 / 假设 / 未知 三栏 |
| `brand.md` | 定位陈述（对谁、解决什么、凭什么不同）；名字与一句话介绍；语气与常用词；视觉要素；不说的话。只写与实验室不同的部分 |
| `marketing-plan.md` | 3 个月目标与衡量方式；目标人群分层；主渠道与理由；阶段计划（每阶段：目标、动作、产物、完成标准）；**当前所处阶段与下一步** |
| `decisions.md` | 只追加：日期、决定、理由、谁定的、推翻了什么 |
| `MEMORY.md` | 目录与现状索引：上面各文件一句话摘要、当前阶段、最近一次进展、待用户决定的事。之后每次工作开始先读它，结束时更新它 |

实验室层面共用的事实（实验室介绍、官号、跨产品的品牌规则）写到 `company/` 对应文件，项目文件里只引用。

## 5. 诊断当前瓶颈，给出下三步

用方法库判断现在卡在哪：有产品读 `workflows/from-existing-product.md`，只有想法读 `workflows/from-idea.md`（通过 `market_library` 工具按需读取，不要一次读完）。找到**最早有证据的问题**，给出下三步，每步写清：

- 做什么、为什么现在做（对应哪条证据或未知）；
- 产物是什么、放在哪个文件；
- 完成标准；
- 用哪个流程或技能（例如起名与定位用 `branding`、落地页用 `workflows/website-conversion.md`、社媒用 `workflows/social-publishing.md` 加 `social_accounts` / `social_publish`）。

把这三步写进 `marketing-plan.md` 的“下一步”，并在回复里列出，请用户确认或调整。

## 6. 交付时的回复

回复简短：已整理哪些材料、写了哪些文件（给出路径）、最关键的 3 个事实、最大的 2 个未知、建议的下三步。不要把文件内容整段贴回聊天。

## 之后每次工作

- 开始：读 `MEMORY.md`，需要细节再读对应文件。
- 结束：把新事实、新决定、新产物路径写回对应文件，并更新 `MEMORY.md` 的“最近进展”。
- 发布过的内容与数据：`social/log.jsonl` 记录了每次发布；复盘时用 `social_read` 读回表现，把结论写进 `marketing-plan.md`。
