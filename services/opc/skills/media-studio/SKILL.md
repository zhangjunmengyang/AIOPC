# 在聊天中制作图片和视频

当前实例已经配置模型。不要索要同一份地址、模型或密钥，不读取或展示私有环境文件。

## 图片

使用 `generate_image`。生成新图时只提供目标和提示词，图片会存进当前项目的 `assets/generated/`；改图时把用户选中或上传的图片路径传给 `reference_images`，清楚描述需要改变和保留的部分。不要用“生成相似图”冒充修改已有图片。保留原图，使用返回的新图片。品牌相关的图先读 `brand.md` 的视觉要素。

返回的是工作区里的实际文件路径。在回复里给出文件路径（工作区内的图片可以直接预览），附一句简短说明；不要把 base64 或工具 JSON 当作图片回复。用户只要图时不附大段制作解释。

如果本次还完成了导出、保存或其他工作，把实际结果和文件链接一并放进媒体消息的 `content`，不要发完图片却漏掉用户要的交付说明。

## 视频

用 `create_video` 创建任务，`request_id` 在同一次用户请求重试时保持不变。提供提示词，按需使用实际存在的首帧。只使用工具 schema 支持的参数，不臆造模型选项。

普通 WebUI 会话中的新视频任务会由网关持久追踪，网关重启后继续查询同一个云端任务，完成后自动下载并发回原会话。创建成功后简短告知正在生成即可，不要连续调用 `wait_video` 占住聊天。用户追问进度时查询原任务。临时会话或直接调用 MCP 不启用持久自动交付，仍按工具结果完成查询和交付。

`get_video` 查询状态，`wait_video` 有界等待，`download_video` 下载已完成结果。创建请求超时可能已经被服务端接受，先查本地任务记录，不自动重复创建。失败时说明实际错误，不把生成中或创建成功当成已经有视频。

提交结果未知时，如果用户从服务端找回任务 ID，使用 `recover_video` 查询验证并关联到原任务，再继续等待，不新建重复任务。

完成后用 `download_video` 取回文件，它会存进当前项目的 `assets/generated/`，在回复里给出路径。

视频任务按 request_id 去重，重复调用不会重复生成。提交结果未知时先用 `get_video` / `recover_video` 核实，不要重新提交。

## 接到项目

某篇稿件要用的图或视频，在稿件的平台稿里写出路径；需要时复制到稿件目录，并记下提示词与用途。用户要“换背景”“改标题”等时继续引用原图；用户要重做时产生新版本，不覆盖旧文件。

图片生成与改图是模型调用，文字侧栏编辑器用于稿件。不要暗示这里有像素级修图、视频时间线或剪辑软件。
